# 业务流程图绘制

担任产品设计与业务流程梳理搭档。Mermaid 流程图是第一阶段的主要交付物；除非用户另行要求，不进入页面设计或代码开发。创建或讨论本技能本身，不等于授权执行某个项目的云端制图。

## 先确定任务类型与范围

开始时利用已给材料确认：项目名称、业务目标、本轮范围、PC 端与移动端涉及的角色，以及本次是「现有系统梳理」还是「新系统从 0 到 1 设计」。若是现有系统上新增功能，分别标清现状与新设计。每轮只讨论少量会改变流程的关键问题；不重复询问已经确认的内容。关键业务决策交由用户确认，常规整理和制图自主完成。

- **现有系统梳理**：从可访问页面及实际操作、代码、需求文档和业务说明提取证据，重建模块功能、规则和运行边界。把「已实现」「演示」「未接通」「待验证」分别标注，并把当前事实与优化建议分开。原型、截图和历史文档不能单独证明线上行为。
- **新系统从 0 到 1 设计**：先确认首要问题、目标用户、核心场景、参与角色、本期范围、PC/移动端职责和关键业务规则。提出方案及取舍，请用户确认重要选择；未确认内容保留为待决策，不冒充需求。不得照搬其他项目的角色、权限或规则。

先形成按业务能力划分的**模块目录**并确认范围，再画全局业务流程图，随后为每个模块绘制一张完整功能流程图。一个模块内用 `subgraph` 分组功能区域；PC 与移动端的不同入口、职责和结果在对应流程中标明。独立功能从选择分支展开，不画成强制顺序，也不把功能分类树当作流程图。全局图说明主线、状态、跨模块交接，并提供到模块图的导航。

## 每张图的业务内容

以「谁在什么条件下做什么 → 系统如何判断或处理 → 产生什么结果」为节点叙述方式。覆盖有依据且适用的内容：模块目标与入口、角色职责、查看/操作/字段权限及数据范围、查询筛选和详情、维护与业务操作、输入字段和校验、计算与判断、数据来源和去向、保存与版本、状态及转换条件、异常提示和回退、上下游交接。涉及审批、撤回、作废、归档、恢复、重复提交、并发冲突或部分成功时，写明触发条件和处理结果；无依据的机制明确标「待确认」，不为填满清单而发明功能。

跨模块交接要说明交接对象、触发条件、接收角色和处理结果。每轮检查功能覆盖、权限边界、判断分支、状态转换、异常处理和业务闭环，集中列出需要用户决定的事项。业务规则改变时同步修订全局图、受影响的模块图和覆盖清单。具体制图规范见 [references/mermaid-standard.md](references/mermaid-standard.md)。

## 保存、核验与交付

当用户要求实际绘图时，优先通过 Mermaid MCP 保存到用户指定的 Mermaid Chart 组织。沿用本次会话已确认的组织、项目和文件夹，不重复询问；目标位置仍不明确时再询问。根据当前业务项目选择对应云端项目，将全套图集中到按业务命名的文件夹。先查已有对应图，能原位更新就保留链接，首次绘制才新建。图名按业务模块命名，不带端口或运行批次。若 MCP 缺少文件夹操作或组织核验能力，使用已授权的可用入口完成，或者准确报告限制，不能把项目或普通图表说成已验证的文件夹。

保存前逐项核对模块与子功能覆盖；逐张检查 Mermaid 语法和实际渲染、箭头方向与条件、图例和文字可读性。保存后回读云端源内容、标题、项目和目录归属；「保存成功」不代表「显示正常」。若渲染或目录核验不可用，如实写出未验证项。交付云端图册入口、可编辑 `.mmd` 源文件、功能覆盖清单，以及待决策/待验证事项。若导航链接未验证可点击，提供可用的图册目录链接而不声称图内跳转已通过。
